# 5 篇公众号正文重新蒸馏：前后质量对比

日期：2026-08-26

模型：本机 Ollama `qwen3:8b`

结构化提示词：`structure.v0.2`

## 一、结论

补入完整正文前，5 篇记录均只有标题或截断导语，处于 `full_text_needs_review`，无法可靠生成 What、Why、证据主张和核验问题。

补入正文后：

- 5/5 通过正文完整度门槛并完成 LLM 蒸馏；
- 5/5 成功分类和路由；
- 4/5 通过事实措辞保真门槛，可进入人工核验队列；
- 1/5 因把来源中的推测性描述升级成确定事实，被自动拦截并降为观察；
- 完整正文共提供 35,683 个可分析字符，避免仅凭标题推断。

这说明正文补抓链路确实改善了信息可知性，同时事实保真门槛发挥了实际作用。但分类路由和部分 What 的表述仍需继续校准，不能直接自动发布。

## 四、仍需修正的规则

1. **推测性来源必须显式归因**：出现“据文章描述”“作者称”“尚不清楚”“仿佛”“可能”等措辞时，What 不得改写为已确认事实。
2. **单一产品案例不得自动上升为行业趋势**：标题中的“进入某时代”“替代某流程”只能作为作者判断，除非有多源证据支持。
3. **一级分类与二级主题分开**：人才计划可以属于“公司战略”，但不应为了满足既有标签被硬塞入“AI Agent 与工具”。
4. **微信公众号仍是二手来源**：完整正文解决的是“可分析性”，不等同于“事实已经核验”；产品发布、融资和模型能力仍需回溯官方来源。

## 五、验收判断

本轮验证通过“完整正文能显著改善蒸馏质量”这一假设，也证明硬门槛能够阻止至少一类明显的事实确定性升级。下一步应把上述三条措辞与分类修正规则写入结构化 Prompt 和确定性校验逻辑，再用同一批 5 篇做回归测试，目标是：5 篇全部完成分析，但不强求全部进入 P1；推测性报道必须被正确归因或保留为观察。
