## 完整版口径

“全市场”指主要公开厂商与代表性模型/产品系列覆盖，不把每个 API SKU、参数量、地区端点重复计数，也不宣称全球不存在遗漏。目录以官方资料为主，保留 `待继续核实`，并通过增量观察持续补充长尾与新版本。

## 数据边界

- `kind` 明确区分基础模型、模型分支、创作产品、AI IDE、Agent 与研究项目。
- `region` 只用于目录筛选，不表示公司的法定注册地或服务可用地区。
- 没有官方发布日期时写 `null`，不把网页更新时间、采集日期当成发布日期。
- `pending: true` 表示名称、当前版本或开放范围仍需继续核实，不阻塞先纳入覆盖观察。
- 目录完整度与版本完整度分开：本轮先完成主要厂商覆盖，后续优先补版本、发布日期和开放方式。许可证与服务地区只在影响使用判断时补充，不作为完整度门槛。

## 持续更新规则

1. 每个条目至少保留一个官方来源。
2. 新模型先匹配母系列；只有产品形态或能力边界显著不同时才新建条目。
3. 版本变更写入既有条目，不重复创建“新模型”。
4. 官网消失、停止服务或被新系列替代时保留历史档案并标注状态，不直接删除。
5. 每次更新校验唯一 ID、分类、HTTPS 来源、区域值和三个自包含预览的数据一致性。

## 核心字段优先级

| 优先级 | 字段 | 完整要求 |
|---|---|---|
| P0 | 版本 | 当前主要公开版本；母系列与具体 SKU 不混算 |
| P0 | 发布日期 | 必须有官方证据；没有证据保留 `null`，不使用网页更新时间代替 |
| P0 | 开放方式 | 区分开放权重、API、网页/App 产品、企业服务、研究预览、未开放 |
| P2 | 许可证 | 仅在影响下载、部署或商业使用判断时记录 |
| P2 | 服务地区 | 仅在存在明显地区限制且影响实际访问时记录 |

## 下一轮数据工作

- 为本轮新增条目补齐当前版本、发布日期证据与版本来源。
- 补齐开放方式：开放权重、API、网页/App、企业服务、研究预览或未开放。
- 许可证、服务地区不做全量补齐，只保留对使用决策有直接影响的信息。
- 将目录从手工快照迁移为独立结构化数据源，再由构建脚本生成在线总览，避免 UI 内嵌数据漂移。
