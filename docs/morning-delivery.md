# 上午交付时间约定

## 2026-09-11 最新规则（优先于下方历史说明）

自 2026-09-14 起，钉钉正式发送已恢复，正常发送时间为每天 10:30；发送仍以当日审核、发布完成和线上期次一致为前提。

网页每日更新。周六周日禁止发送钉钉，包括手动恢复和重发入口；周一采集窗口至少回溯至周六00:00，按当天审核稿汇总，不逐条补发周末旧期次。

配图自动化已改为每日10:10一次启动，最多等待60分钟就绪；就绪后30分钟内0/10/20分钟最多3次尝试，持久计数，恢复不清零，不再固定10:15/20/25消耗机会。不是全天轮询。机器睡眠或超过等待窗口仍不能保证交付，必须报告。

启动先做DNS与公网地址预检（不等于HTTPS全部可达）；采集后写入early-publication-mode.json，覆盖不足仅建议有限发布，仍需用户明确同意。第一轮事实审核、第二轮中文化审核和配图预览都会打开可操作的 Terminal 窗口；第二轮全部通过后自动续跑。系统调用失败不记为“已提醒”，最多重试3次。端到端准点与系统弹窗实际到达仍需真实晨跑验收。

北京时间：08:00 采集；09:00–10:10 电脑可能睡眠；10:10 再触发 daily_runner 从既有状态恢复或提示人工审核；10:15 为人工事实审核目标截止，不代表自动批准。

配图流程由 10:10 的恢复任务启动，按原图、官方素材、AI兜底的顺序处理，并在图片就绪后进入第二轮配图预览；人工通过后自动恢复语义复核和发布。它不是全天轮询，也不会把提醒当成审核批准。

钉钉本机检查固定为每天 10:30 一次，无 RunAtLoad、无全天轮询。联合发布只在质量通过且网页当期可访问后发送；完成回调会以60秒间隔等待 GitHub Pages 生效，最长30分钟。既有 sent 标记会在网络检查前去重，也不调用生图模型。2026-09-14 的 12:30 为一次性补发例外，不进入日常 LaunchAgent 配置。

10:30 为交付目标，不是绕过质量审核的截止阀门。事实未审核、图片不合格或部署未完成时保留阻塞状态，不自动批准、不虚报发布。仅短讯发布必须满足已有兜底规则。

限制：本机睡眠期间不保证执行；10:10 必须开盖、解锁、联网并保持 Codex 在线。审核后写作仍可能超过15分钟，预先生成待审草稿的架构尚未实现，因此不能承诺明日必定10:30完成。macOS 可能合并睡眠期间的定时事件，不能将其当作准点运行证据。

安装：`.venv-llm/bin/python scripts/install-morning-schedule.py --apply`，备份原 plist 后重新加载并验证服务已注册；不直接采集或发送。
