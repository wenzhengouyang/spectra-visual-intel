# 有限采集闭环与审核样本 · 2026-09-11

## 本批工程范围

1. `safe_http.py`：采集器与定向补搜共同使用固定 DNS 地址连接。HTTP/HTTPS 每次跳转重新检查；拒绝非公网地址、非常规端口、凭据 URL、HTTPS 降级、POST 跳转。跨来源跳转移除认证和 Cookie；不读取环境代理。WeRSS 只允许明确配置的回环源地址，不能以该例外访问其他内部地址。
2. `acquisition-budget.sqlite`：同一期所有采集子进程、arXiv Atom、WeRSS API、网页下载和补搜请求共用 180 次本机 HTTP 请求预算，失败也计数，断点重启不清零。同域间隔默认 1 秒，arXiv 翻页额外等待 3 秒。写作模型和发布不使用这份采集预算。第三方服务内部的搜索/抓取请求无法由本机逐次计数，不能声称覆盖其内部流量。
3. 离线提取：主进程受控下载，macOS 沙箱只解析正文，不允许联网、创建子进程或读取项目外任意文件；清除密钥环境变量，限制 CPU、输出和执行时间。沙箱不可用时拒绝执行。旧网络型 extractor 命令不再无隔离运行；JS/登录/验证码页面可能降级为提取不足，需后续独立、受控的浏览器采集适配，不绕过访问限制。
4. 定向补搜：结构化结束后自动执行，每候选最多 2 个查询、每期最多 4 个查询，每查询最多保留 3 个来源。每次 Responses 请求最多 1 次内置工具调用、1500 输出 tokens，补搜阶段目标上限 180 秒；保存原始来源 bytes、最终 URL、摘要哈希和接口 usage。来源不自动成为 verified，不修改事实审核结论。
5. 状态持久化：查询前保存 attempt；完成后保存来源。重复执行复用结果，进行中断掉的查询标记人工检查，不自动重复扣费。鉴权/余额错误立即熔断该期补搜；其他来源和正常采集仍继续。`candidates.evidence-search.json` 和进度页显示状态。
6. 审核样本：事实审核提交、通过校验后的最终事实、图片审核形成本地 `review-samples.sqlite`。保存输入、修订/删除/保留结果、来源、审核主体、原因和图片文件指纹。相同提交幂等去重；未声明主体标记 unspecified，不猜测为人工。默认全部 training_eligible=false，后续还需人工整理数据集，不自动训练/上传。新任务同时保存 `review-input.json`；旧任务缺基线时明确标记，不伪造修改前内容。

## 实测与阻塞

- 315 项回归通过（包含临时 HTTP 服务器 404、429、超时、重定向到内网拦截，固定 IP 连接，跨连接预算，真实沙箱文件/网络/子进程拒绝，补搜恢复/熔断，样本去重）。
- 公网官方网页 TLS 读取成功，计入 1 次请求。
- GitHub 工程副本额外查出此前遗漏的事实扩展模块与旧核验规则，已补齐对应源码；调度回归改为校验现有安装器的有限时间计划，不再依赖未分发的旧本机 plist 模板，不更改已安装任务。
- 真实补搜测试共发出 2 次接口请求，第二次用于只输出安全错误码的诊断。现有接口返回 `429 / credit_balance_exhausted`，尚未取得成功的真实搜索结果。没有充值、换供应商、重发新闻或钉钉。
- 余额恢复前，定向补搜仍不能宣称实际可用；其失败不会自动批准缺证据内容。

## 运维边界

- 用户暂缓付费补搜后，入口默认关闭；仅当 processor 配置显式设置 evidence_search.enabled=true 才调用。关闭期间不触发 API，也不把额度问题计为主流程失败。已有资料检索与官方原文补证的三级兜底仍未完整实现。

- 不新建轮询任务，不改变用户规定的图片检查次数/时间，不增加无限重试。
- 本机沙箱实现针对当前 macOS；其他系统缺少对应实现时 fail closed，不能直接宣传跨平台就绪。
- 同一期发生 provider_block 后不会自动反复试探；恢复余额后应显式排查并重新开启受限查询，或在新一期重新尝试。保留旧失败证据，不删除预算账本以绕过上限。
- 该改动是工程闭环加固，不等于长期稳定性验收或整个项目 90% 完成。

接口依据：[OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)、[Responses max_tool_calls](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。
